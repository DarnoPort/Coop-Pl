# Проверки

## Автоматические проверки

В PowerShell из корня репозитория:

    cd server
    npm.cmd install
    npm.cmd test

Тесты находятся в соседнем каталоге tests/, а зависимость ws устанавливается в server/node_modules/. Интеграционный тест явно разрешает ws относительно каталога пакета сервера, поэтому установка зависимости в этом пакете работает и в Windows.

Синтаксическую проверку плагина, находясь в каталоге server, запускай так:

    node --check ../plugin/CoopPl_Core.js

Скрипт tests/protocol.test.js проверяет валидацию пакетов, tests/server.test.js запускает настоящий WebSocket-сервер и двух WebSocket-клиентов, а tests/plugin.test.js загружает плагин в минимальный mock-runtime RPG Maker для проверки базового цикла подключения и remote sprite. Эти проверки не заменяют запуск двух настоящих экземпляров MZ.

## Если вторая игра MZ сразу закрывается

У RPG Maker MZ есть известный практический обходной путь для ситуации, когда одновременно не запускаются два экземпляра игры: задать Chromium/NW.js отдельный пользовательский каталог через `chromium-args`. В проекте Michael Way – Double Way уже есть эта настройка:

```json
"chromium-args": "--force-color-profile=srgb"
```

Не удаляй текущий аргумент `--force-color-profile=srgb`. Для проверки сделай две отдельные копии проекта и в каждой измени только значение поля `chromium-args`, добавив уникальный профиль:

Копия хоста:

```json
"chromium-args": "--force-color-profile=srgb --user-data-dir='.\\\\nwjs-profile-host'"
```

Копия гостя:

```json
"chromium-args": "--force-color-profile=srgb --user-data-dir='.\\\\nwjs-profile-guest'"
```

Это поле должно находиться внутри уже существующего объекта `package.json`; не добавляй второе поле с тем же именем. Сохрани JSON-формат: запятые между соседними свойствами обязательны, после последнего свойства запятая не нужна. Папки профиля будут созданы Chromium/NW.js; имя профиля в двух копиях должно отличаться.

После изменения полностью закрой окна тестовых игр. В диспетчере задач проверь, что не осталось процессов `Game.exe` или `nw.exe`, относящихся к этим тестам, затем перезапусти сервер и сначала одну, потом вторую копию игры.

Если тест запускается из Playtest и настройка в проектном `package.json` не меняет поведение, сделай отдельное **Deployment → Windows** для двух копий и попробуй запустить каждый экспортированный `Game.exe`. Официальная справка MZ описывает запуск Windows-сборки именно через `Game.exe` в папке игры: https://rpgmakerofficial.com/product/MZ_help-en/01_06.html. В экспортированных папках также проверь их `package.json` и сохрани уникальные значения `user-data-dir`.

Это обходной путь для тестовой среды, а не исправление Coop-Pl. Если вторая игра по-прежнему закрывается, проверь, появляется ли второй процесс в Диспетчере задач и есть ли сообщения об ошибках в консоли разработчика (F8 в режиме Playtest).

## Запуск сервера локально

Требуется Node.js 20 или новее.

    cd server
    npm install
    npm start

Сервер по умолчанию слушает 127.0.0.1:8080. Для доступа с другого компьютера в доверенной локальной сети запусти его явно с привязкой ко всем интерфейсам.

PowerShell:

    $env:COOP_HOST = "0.0.0.0"
    $env:COOP_PORT = "8080"
    npm start

Для подключения двух копий на одном компьютере используй ws://127.0.0.1:8080 в параметре ServerUrl. Для второго компьютера в той же LAN используй ws://<LAN-IP-хоста>:8080 и разреши входящий порт в Windows Firewall, если он заблокирован.

Не выставляй сервер в публичный Интернет: сейчас нет шифрования или аутентификации.

## Тест в RPG Maker MZ

1. Сделай копию проекта, не тестируй на единственном оригинале.
2. Скопируй plugin/CoopPl_Core.js в копию проекта, в js/plugins/.
3. В Plugin Manager включи CoopPl_Core.
4. Для обеих копий укажи один ServerUrl и RoomCode, но разные PlayerName.
5. Запусти сервер, затем обе копии игры.
6. Проверяй только после подтверждённого сообщения connected в игровом логе и появления удалённого персонажа.

### Условия PASS для первого сетевого теста

- Оба клиента подключаются к той же комнате.
- Каждый клиент видит другого игрока на той же карте.
- Движение и направление обновляются без постоянного дублирования персонажей.
- После выхода одного клиента у другого исчезает его sprite.
- Повторное подключение не оставляет фантомного игрока.
- Переход игрока на другую карту не показывает его sprite на неправильной карте.
- Ошибка сервера или отключение не приводит к зависанию игрового цикла.

До выполнения этого теста статус интеграции остаётся непроверенным.
