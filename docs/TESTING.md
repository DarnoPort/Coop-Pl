# Проверки

## Автоматические проверки

Из корня репозитория:

    cd server
    npm install
    npm test

Синтаксическая проверка плагина:

    node --check plugin/CoopPl_Core.js

Изолированные проверки в этом репозитории не заменяют запуск MZ. Результат должен различать прошедшие unit-тесты и непроведённую игровую проверку.

## Запуск сервера локально

Требуется Node.js 20 или новее.

    cd server
    npm install
    npm start

Сервер по умолчанию слушает 127.0.0.1:8080. Для доступа с другого компьютера в доверенной локальной сети запусти его явно с привязкой ко всем интерфейсам.

PowerShell:

    $env:COOP_HOST = "0.0.0.0"
    $env:COOP_PORT = "8080"
    npm start

Для подключения двух копий на одном компьютере используй ws://127.0.0.1:8080 в параметре ServerUrl. Для второго компьютера в той же LAN используй ws://<LAN-IP-хоста>:8080 и разреши входящий порт в Windows Firewall, если он заблокирован.

Не выставляй сервер в публичный Интернет: сейчас нет шифрования или аутентификации.

## Тест в RPG Maker MZ

1. Сделай копию проекта, не тестируй на единственном оригинале.
2. Скопируй plugin/CoopPl_Core.js в копию проекта, в js/plugins/.
3. В Plugin Manager включи CoopPl_Core.
4. Для обеих копий укажи один ServerUrl и RoomCode, но разные PlayerName.
5. Запусти сервер, затем обе копии игры.
6. Проверяй только после подтверждённого сообщения connected в игровом логе и появления удалённого персонажа.

### Условия PASS для первого сетевого теста

- Оба клиента подключаются к той же комнате.
- Каждый клиент видит другого игрока на той же карте.
- Движение и направление обновляются без постоянного дублирования персонажей.
- После выхода одного клиента у другого исчезает его sprite.
- Повторное подключение не оставляет фантомного игрока.
- Переход игрока на другую карту не показывает его sprite на неправильной карте.
- Ошибка сервера или отключение не приводит к зависанию игрового цикла.

До выполнения этого теста статус интеграции остаётся непроверенным.
